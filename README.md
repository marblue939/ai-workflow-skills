# AI Workflow Skills · 求职与内容生产工作流

一套把「日常重复流程」沉淀成可复用 skill 的实践集合。每个 skill 都是纯 Markdown + 可选脚本，能被 Claude Code、Codex、DSH 等支持 `SKILL.md` 约定的 agent 直接加载，也可以当人工检查清单用。

## 为什么有这套东西

用 AI 做交付，真正的瓶颈不是「AI 能不能写」，而是**流程有没有被写清楚**：目标、边界、验收标准写成文字，AI 的输出才可验收；反复踩过的坑固化成规则，下一轮才不会重踩。

这个仓库是我在做求职管线（JD 筛选 → 简历定制 → 拆解文档 → 台账更新 → AI 产出验收）时，把每个环节稳定下来的做法抽象出来的结果。它不是提示词收藏夹，而是一组**带验收口的流程定义**。

## 目录

```
skills/
├── jd-screening/          # JD 输入 → 三件套（定制招呼语 / 简历版本 / 红旗检查）
├── resume-tailor/         # 按 JD 打靶改简历：映射表 → 重排 → 双闸口
├── game-doc-breakdown/    # 品类/竞品拆解报告的结构与质量检查
├── ledger-update/         # 台账（Excel）安全更新：先备份、按名定位、写完断言
└── ai-output-verify/      # AI 生成代码/文档的验收门禁
```

## 安装

**Claude Code**：把 `skills/<name>/` 放进项目的 `.claude/skills/`，重启会话后按 description 自动触发。

**DSH / 其他支持 SKILL.md 的 agent**：把目录加入对应 skills 搜索路径即可。

**不想装**：每个 SKILL.md 本身就是一份可执行的人工检查清单，直接照着做。

## 使用示例

```
> 这份 JD 帮我看看值不值得投，顺便出个打招呼的话
（触发 jd-screening → 输出：岗位判断 / 招呼语 / 红旗 / 岗位→简历速查表）

> 按这个 JD 改简历，注意别编造
（触发 resume-tailor → 输出：JD 要求→简历证据映射表 / 缺失项标注 / 重排说明）

> 把这次投递状态记进台账
（触发 ledger-update → 备份 → 按公司名定位 → 改完回读断言）
```

## 设计原则

1. **每条结论都要有出口**：写判断，也写判断依据和验收方式。
2. **缺口如实写**：没有的经历就标「不写」，不用形容词补。
3. **改动可回滚**：凡是写文件，先备份、再改、改完回读校验。
4. **流程可复用**：一次踩坑 → 写进对应 SKILL.md 的检查项，而不是记在脑子里。
