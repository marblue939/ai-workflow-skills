# JD 筛选与三件套

## 何时触发

- 用户甩 JD 截图 / JD 链接 / JD 文本，没有额外说明（默认就是要「判断 + 招呼语」）
- 用户在挑岗位，需要「值不值得投」的判断

## 输入

1. JD 原文（截图先 OCR/读图；缺字段就标注「截图中未含」）
2. 用户画像与红线（见 `references/profile.md`，使用前替换成自己的）
3. 现有台账（岗位是否已在投、是否重复）

## 步骤

1. **抽取 12 个字段**：公司 / 城市 / 岗位名 / 薪资 / 经验或届别 / 规模 / 融资 / 职责 3~5 条 / 任职要求 / 加分项 / 招聘者 / 截止时间。
2. **重复检查**：同公司同岗位是否已在台账；同公司不同岗位要分开记，并提示「能否同时投」。
3. **匹配度打分（1~5）**：逐条对照任职要求与加分项，标 ✅ 命中 / ⚠ 部分 / ✗ 缺口，**缺口必须写「不写」，不许用形容词补**。
4. **写招呼语**（60~100 字，2~3 句）：
   - 不报姓名（对方看得到），身份用一句「XX专业 XX 届本科」；
   - 只讲 JD 最重的 1~2 个要点 + 明确求职意向；
   - 无括号补充、无「熟练」等未确认的能力词、到岗只表意向（「接受 XX 线下，确认后尽快到岗」）；
   - 冷启动：不主动提旧面试与历史投递。
5. **给红旗**：届别不符、经验年限、加班/抗压、长实习、城市降权、规模不符偏好、要求未确认过的技能。
6. **出速查表**：岗位 → 该发哪个简历文件（一岗一行）。

## 输出模板

```
## 结论（一行）
匹配度 x/5，建议：投 / 先问再投 / 不投

## 招呼语（可复制）
> ……

## 简历
文件名 + 采用哪个版本 + 为什么（无增项就说明为什么复用）

## 红旗
- ……

## 岗位→简历速查
| 公司 | 投这份 |
```

## 自检

- [ ] 招呼语里没有括号补充、没有「上线」类夸大、没有未确认能力词
- [ ] 每个缺口都明确写了「不写」
- [ ] 速查表文件名与实际文件一致
