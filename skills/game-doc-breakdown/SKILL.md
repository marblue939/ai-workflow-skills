# 品类拆解报告骨架与检查

## 何时触发

- 要写一份品类/竞品拆解当作品集
- 手上已有拆解文档，要判断哪里不合格（常见问题：全是结论、没有对照、数字与简历打架）

## 骨架（可裁剪）

1. **拆解对象与方法**：拆哪几个系统、参照哪些标杆、结论在哪个自研项目里复现验证。
2. **核心循环**：一张表讲清层级 / 循环路径 / 情绪价值 / 对应系统。
3. **分系统拆解**：每个系统给「设计约束 + 取舍 + 可复用结论」，避免写成玩法介绍。
4. **标杆对照表**：维度 × 标杆产品 × 自研项目。这一张表最能体现「拆过」而不是「玩过」。
5. **验证方法**：自动化断言 + 实测统计（如死亡集中点、通过率曲线），并说明数据来源。
6. **可复用结论**：编号列 5~8 条，每条能直接指导设计动作。
7. **结语**：落点回到「结构可迁移」，不喊口号。

## 质量检查

- [ ] 每个结论都有「因为…所以…」的依据，不是断言式结论
- [ ] 有横向对照表，且对照维度能看出差异，不是三列写一样的话
- [ ] 文档里的数字与简历、项目说明一致（数量、关卡数、断言数）
- [ ] 没有出现「上线」类未经证实的表述；自研成果一律写「完整可运行版本」
- [ ] 表格有编号与表注；标题层级统一
- [ ] 术语首次出现给中英文，后文统一

## 常见坑

- **只写自研结论** → 加对照表
- **数字前后不一致** → 建立「事实数字表」，全项目共用一套
- **写成产品介绍** → 每段末尾必须落到设计动作或取舍
