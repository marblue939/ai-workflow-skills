# 按 JD 打靶改简历

## 何时触发

- 用户给了 JD 并要「发简历 / 改简历 / 出专属版」
- 用户质问「这份简历凸显了 JD 要求吗」——这类问题通常意味着上一版只是改名复用

## 硬规则

1. **光改名复用不算交付**。没有真实增项也要给映射表，并说明「为什么不需要改」。
2. **数字永不改**，只重排与增补真实项；没有的经历不补。
3. 改完必须过双闸口：**docx 全文断言**（新增句在、禁词无、关键数字在）+ **渲染图视觉验收**（标题横幅、断字、孤行、页码位置）。

## 步骤

1. **映射表**：JD 每条职责/任职/加分项 → 简历里对应的句子 → 标 ✅/⚠/✗。缺口写「不写」。
2. **定改法**：把 JD 最重的 1~2 条顶到「个人优势」前两条；把对应证据从项目经历里摘出来重写，不新增未经证实的经历。
3. **生成**：用模板脚本生成 docx（保留统一版式），脚本里做 `replace + assert count==1`，防止静默失败。
4. **断言**：python-docx 读全文，检查新增关键词、禁词（未确认技能/夸大表述）、关键数字。
5. **转 PDF + 渲染**：LibreOffice 转 PDF，PyMuPDF 渲染每页 PNG，逐页看：横幅白底浅字、断字、孤行、页码、页数形态（如第 3 页只有教育块属正常）。
6. **回报**：改了什么、对应 JD 哪一条、没改什么、缺口是什么。

## 输出模板

```
简历：<文件名>（N 页，过双闸口）
| JD 要求 | 改后表达 | 判定 |
| …… | …… | ✅/⚠ |
缺口：<逐条列出，标注不写>
```

## 自检

- [ ] 映射表覆盖 JD 全部职责与加分项
- [ ] 新增句都能在原始项目事实里找到依据
- [ ] 禁词扫描为 0（未确认技能、夸大词、编造数字）
- [ ] 渲染图逐页看过，不是只看了文件生成成功
